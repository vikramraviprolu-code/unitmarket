# 02 Top 12 problems, ranked by impact times ease

Impact (I) runs from 1 to 5 and means how much the problem hurts trust or completion on the demo path. Ease (Z) runs from 1 to 5, where 5 is a copy or CSS change of an hour or less. Rank = I x Z, highest first. Fix size is one of: copy only, CSS, layout, new component, data (a view field read from stored data in `apps/web`), or behaviour change. MONEY PATH marks anything on the approval, step, order or receipt pages; those need the payments reviewer.

## Also found (smaller, cheap, worth doing with the above)

- "$1.20 for read online" reads badly (`FitCard.tsx:53`). Use "$1.20 · Read online" with "5 days to read" under it. Copy only.
- Every result says "Good fit", even where the topic row says "weak" (106.webp). Do not change the band (it comes from `domain/fit`). Instead, show the topic evidence as the one-line summary so the cards differ: "Matches 2 of 4 of your words · 12 months old". Copy and layout, apps/web only.
- The fit card title is not a link, so the abstract is never seen from search (`FitCard.tsx:46`). This needs `publisher_slug` and `offer_code` in the discover item, which the route can add from `offer_id` in apps/web.
- The offer page asks the buyer to press "Show my price" for a price already shown in the option list (22.webp). In the quick wins, rename the button "Get my price and terms". In the medium set, auto-quote on option change; that is a behaviour change, so the payments reviewer must confirm that quote creation stays harmless.
- "Evidence" and "Payment state: refunded" on the library item page (91.png) are internal words. Use "Details" and words for the state.
- The help page has no index, and "We opened a case and will update this page." promises an update the page never shows (`OpenCase.tsx:31-33`). Use "We opened a case. We will tell you the outcome on your order page." Do this only if that is true (the order page shows `open_case`), otherwise use "We opened a case and will look at it."
- Disabled primary buttons are 55 % opacity blue with white text (16.png). Use a neutral disabled style (surface-2 background, muted text, line border) so they read as "not yet" rather than "broken".
- Contrast, measured: the border token `--line: #8a93a0` reaches 3.11:1 on white but only 2.98:1 on the page background `#fbfaf7` (`globals.css:8,4`). That background sits next to the textarea, input and fieldset borders, so it is a hair under the WCAG 1.4.11 minimum of 3:1. Change `--line` to `#7a8491`, which gives 3.79:1 on white and 3.48:1 on the proposed `#f6f5f1`. CSS only.
- Home card "I have an article link" holds a list, not a link field. Rename it "Browse articles".
- Date and time everywhere are `YYYY-MM-DD HH:MM UTC` (`lib/format.ts:26-28`). Use "29 Oct 2026, 19:14 UTC". No test pins the format (grep found no test that uses `formatDateTime` or a UTC string).
- A security point, outside this UX review: the buyer receipt API returns the snapshot with `payee_merchant_id`. READINESS already lists "merchant id redaction at the buyer API" as open. The UI does not show it; keep it that way.

# CO-1d: webhook certificate pin, learn-only window (D-038)

Task: let the owner learn the webhook certificate facts from one real delivery without ever trusting them, and make the pin gate require the full pin.
Package: `packages/paypal`, `packages/config`, `apps/web` (webhook behaviour and composition wiring), docs Owner: Sonnet 5.5 builder, effort high (public route, money-adjacent, certificate trust) Reviewer: Opus 5.5 high; Sakthi merges
Assumptions: ASM-54, ASM-64, ASM-66, ASM-71. Decisions: D-038 (learn only), D-029, D-035 (five locks, sealed transport).

Goal: while a time-limited learn window is open, a delivery to `POST /api/webhooks/paypal` is answered 503 and acts on nothing: no verification verdict is used, no event is stored, no read-back is scheduled, no order, ledger or entitlement row changes. The app only records the certificate facts: host, path, subject (full DN and CN), issuer DN, validity dates and the SHA-256 fingerprint, as one `audit_log` row (`webhook.cert_learned`, actor system) and one log line of the same name. Never the body, the signature, the transmission id or the cert URL query. The certificate is read by a new `inspect(url)` on the existing certificate source: same `guard` (https, one label under `sandbox.paypal.com`, certificate path, no redirects), same transport (`fetch_webhook_cert`, five locks), same admit budgets (cold 6 an hour, then 1 an hour and 12 a day for unknown URLs), same size and time limits; it never fills the verification cache, never calls `trust()`, never skips or relaxes a check. One row per distinct certificate (host, path, fingerprint): a repeat is answered 503 with no fetch and no row. The window is `UMS_WEBHOOK_CERT_LEARN_UNTIL`, a UTC time `YYYY-MM-DDTHH:MM:SSZ` (milliseconds only as exactly three digits) read only in `packages/config`: refused at boot outside sandbox mode, when malformed, or when more than 24 h after boot (checked with the injected clock in composition); a past value is ignored (window closed). Open means `now < until`. An open window ends on its own at `until`, so it cannot stay open longer than 24 h from boot. The `webhook_enabled` switch must be on. Window closed: behaviour is unchanged.
Also: (1) the pin is a full pin, `EXPECTED_CERT_PINS: readonly { host, subject, issuer }[]` (exact host, subject and issuer; `EXPECTED_CERT_SUBJECTS` is removed); the sandbox gate needs a non-empty list in which every entry is full and its host is a certificate host the guard allows; a certificate passes only if its URL host, subject and issuer all equal one entry. (2) ASM-71 records that trust is seeded at boot from the committed pin and that a learn window never trusts. (3) `MVPC-OWNER-STEPS.md` Step 7 becomes the learn procedure (Steps 1, 3, 6 untouched); Step 9 follows. (4) `hosting.md` names the window.

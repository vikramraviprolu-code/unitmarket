# DP-1: composite snapshot gates, settlement route and supply data

Task: freeze the per-publisher settlement route in a two-publisher snapshot, cap a pack at two publishers, prove the P18 and mixed-currency gates for a composite, and add the supply data a USD two-publisher pack needs without moving any existing seed id.
Package: `domain/approval`, `packages/contracts` (approval), `domain/catalogue` (supplementary seed), `packages/testkit` (opt-in), `packages/db` (migration 0010) Owner: Sonnet 5.5 builder, effort medium Reviewer: Opus 5.5 medium; Sakthi merges
Wave: MVP-D W1, first lane. Decisions: D-041 (owner, decided: OQ-1 = B and OQ-18). Coordinator decisions used: OQ-9, OQ-12, OQ-15 (table A). Requirements: D-04, D-07, P18, P5 (snapshot side), A-08, A-09.

Goal. (1) `requestApproval` refuses a selection from more than `MAX_PUBLISHERS = 2` publishers with `too_many_publishers` (422) before any row is written. (2) Only a snapshot with two publishers gains `settlement: { route: 'per_publisher'; payments: 2 }`, inside the canonical hash; a one-publisher snapshot is built exactly as today, so its `content_hash` does not change (L1). `ApprovalSnapshotSchema` accepts `settlement` as optional and refuses `payments` that differs from the publisher count, `route: 'single'` and `settlement` on a one-publisher snapshot. `placeOrder` (DP-2a) treats a two-publisher snapshot without `settlement` as an invalid approval. (3) P18 and D-07 already hold in code; this lane proves them for a composite. (4) Supply (M4): a new `SEED_SUPPLEMENT_COMPOSITE` block (one fictional US publisher `quayside-gazette`, "Quayside Gazette (fictional)", two short team-written articles, two authorised USD offers `BOTH(150, 120)` and `BOTH(90, 90)`) applied by `seedSupplement(db, clock, ids, block)` after the base seed. It is idempotent by slug and key, so it can run on every boot (DP-5 calls it from composition) and reaches an existing persistent disk. It takes its own `Ids` (tests use `seededIds('seed-composite')`), so `SEED_DATA` and every id of the base seed stay as they are. `seedTestCatalogue` in `packages/testkit` gains an opt-in `{ composite: true }` that applies the supplement with `seededIds('testkit-catalogue-composite')`; without it, nothing changes. Mirror: `fixtures/catalogue/seed-composite.json`. (5) Migration `0010_publisher_payee_shared.sql` (M5, required by D-041): adds `payee_shared boolean NOT NULL DEFAULT false`, drops `publishers_paypal_merchant_id_key`, and adds `CREATE UNIQUE INDEX publishers_merchant_unshared ON publishers (paypal_merchant_id) WHERE NOT payee_shared`. Two rows may share a merchant id only when both carry the explicit flag; the flag is set only by the audited seeding step of DP-5. The publisher row stays the unit of attribution. Forward-only. Because the partial index alone admits one flagged and one unflagged row with the same id, 0010 also adds a row trigger `publishers_payee_guard` (BEFORE INSERT OR UPDATE OF paypal_merchant_id, payee_shared). It takes a transaction advisory lock per merchant id and raises 23505 unless both rows are flagged. The function is SECURITY DEFINER with search_path = pg_catalog, pg_temp and a schema-qualified public.publishers. It is correct under READ COMMITTED and SERIALIZABLE; writers must not use REPEATABLE READ (the trigger refuses a merchant-id write there with serialization_failure).
